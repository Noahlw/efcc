## 3. Detailed Finding Cards

### F-01: Floating dock overlaps `停止掃描` button by 40px at 320×568
* **Severity:** **Major**
* **Surface:** `/scanner` (phone live camera state)
* **Viewport:** 320×568 (iPhone SE 1st gen)
* **Steps to Reproduce:**
  1. Login as Member and navigate to `/scanner` at 320×568 viewport.
  2. Wait for camera to open (`data-camera-state="live"`).
  3. Observe the bottom of the screen where `.cameraStop` ("停止掃描") meets the navigation dock.
* **Expected Result:**
  The `停止掃描` action button sits fully above the floating dock with $\ge 8\text{px}$ clearance, allowing unhindered tapping.
* **Actual Result:**
  `.cameraStage` has `min-height: 560px` and `.cameraStop` has `bottom: 24px` (`@media (max-height: 640px)`). This positions the button from $y=488\text{px}$ to $y=536\text{px}$. The fixed navigation dock sits at $y=496\text{px}$ to $y=558\text{px}$. The dock overlaps the `停止掃描` button by exactly 40px (from $y=496$ to $y=536$), intercepting user taps.
* **Evidence:**
  * Screenshot: `docs/qa/screenshots/scanner-dock-check-320x568.png`
  * Bounding Rects: `stopBtn` `{ x: 20, y: 488, width: 280, height: 48 }`, `dock` `{ x: 14, y: 496, width: 292, height: 62 }`.
* **Contract-Safe Remediation:**
  In `web/lib/attendance-panel.module.css`, adjust `@media (max-height: 640px)` for `.cameraStage`: reduce stage padding / viewfinder size and position `.cameraStop` at `bottom: calc(76px + env(safe-area-inset-bottom, 0px))` so the button clears $y=496\text{px}$.

### F-02: Floating dock obscures escape action `不是這個聚會` on viewports $\le 700\text{px}$ height
* **Severity:** **Major**
* **Surface:** `/scanner` (`ScannerConfirmation` screen)
* **Viewport:** 320×568, 375×667, 375×700
* **Steps to Reproduce:**
  1. Open `/scanner?manual_code=482913` on 375×667 (iPhone SE 2/3) or 320×568 (iPhone SE 1).
  2. Observe the confirmation card (`ScannerConfirmation`).
  3. Check the visibility of the secondary escape action `不是這個聚會`.
* **Expected Result:**
  Both `確認簽到` (primary) and `不是這個聚會` (secondary escape) are visible above the floating dock without requiring internal scrolling.
* **Actual Result:**
  * At 320×568: `不是這個聚會` is pushed to $y=583.2\dots 628\text{px}$ (completely below the 568px viewport fold).
  * At 375×667: `notThisBtn` sits at $y=587.6\dots 632.4\text{px}$, which is 37.4px overlapped by the fixed dock ($y=595\dots 657\text{px}$).
  * At 375×700: `notThisBtn` bottom is $y=632.4\text{px}$, overlapping dock top ($y=628\text{px}$) by 4.4px.
* **Evidence:**
  * Screenshots: `docs/qa/screenshots/scanner-confirm-320x568-layout.png`, `docs/qa/screenshots/scanner-confirm-375x667-layout.png`, `docs/qa/screenshots/scanner-confirm-375x700-layout.png`
  * Bounding Rects (375×667): `notThisBtn` `{ x: 37, y: 587.6, width: 301, height: 44.8 }`, `dock` `{ x: 14, y: 595, width: 347, height: 62 }`.
* **Contract-Safe Remediation:**
  In `web/lib/attendance-panel.module.css`, add a short-height media query `@media (max-height: 720px)` targeting `.page`: reduce top padding from `2rem` to `0.75rem`, reduce `.confirmHeader` height to `1.5rem`, and reduce `.confirmDetails` gap so the entire card height remains $\le 520\text{px}$.

### F-03: Network failure on confirmation screen hides `重試簽到` button
* **Severity:** **Major**
* **Surface:** `/scanner` (`ScannerConfirmation` screen)
* **Viewport:** 375×844, all viewports
* **Steps to Reproduce:**
  1. Resolve an event to reach `ScannerConfirmation`.
  2. Simulate network disconnection or server timeout (e.g. offline drop).
  3. Click `確認簽到`.
  4. Observe the displayed error and action buttons.
* **Expected Result:**
  Per Spec F-11, an error explains the submission failure (`未能提交簽到。請重新連線後再次確認；系統不會自動重試。`) AND a dedicated secondary `重試簽到` button appears and receives focus so the user can easily re-attempt.
* **Actual Result:**
  `p.confirmError` renders the failure message, but `self-check-in-panel.tsx:276` runs `setRetryAvailable(!offline)`. Because `offline` is true on network errors, `retryAvailable` is set to `false`. Consequently, `{retryAvailable && <button ...>{COPY.attendance.retry}</button>}` is omitted from the DOM, leaving only `確認簽到` and `不是這個聚會`.
* **Evidence:**
  * Screenshot: `docs/qa/screenshots/hunt-offline-confirmation-state.png`
  * Code inspection: `self-check-in-panel.tsx:276` (`setRetryAvailable(!offline)`).
* **Contract-Safe Remediation:**
  Update `self-check-in-panel.tsx:276` to `setRetryAvailable(true)` on network errors and non-permanent failure codes so the user receives the promised retry control.

### F-04: Viewfinder remains frozen in live state when video track is terminated by OS
* **Severity:** **Major**
* **Surface:** `/scanner` (`scan-live` camera state)
* **Viewport:** 375×844, all viewports
* **Steps to Reproduce:**
  1. Open `/scanner` with camera live.
  2. Revoke camera permission in browser/OS settings, switch camera source, or trigger a hardware stream interruption (`track.stop()`).
* **Expected Result:**
  `useQrCamera` detects stream track termination via `track.onended` / `track.addEventListener("ended")`, stops the decoding loop, and transitions to the `fallback` state with an explanatory message (`相機掃描不可用` or `相機權限未開啟`).
* **Actual Result:**
  `useQrCamera.ts` sets up no listener for track `ended` events. The camera surface stays stuck in `data-camera-state="live"`, presenting a frozen, unresponsive video frame with no feedback to the user.
* **Evidence:**
  * Screenshot: `docs/qa/screenshots/hunt-camera-track-ended-freeze.png`
  * Code inspection: `use-qr-camera.ts:258-289` (no track `ended` event listener).
* **Contract-Safe Remediation:**
  In `use-qr-camera.ts:268`, attach `track.addEventListener("ended", () => { stopCamera(); reportUnavailable(); });` to every acquired video track.

### F-05: Validation error placed below submit button triggers 76px scroll jump on 320×568 guest form
* **Severity:** **Major**
* **Surface:** `/guest-check-in`
* **Viewport:** 320×568 (iPhone SE 1st gen)
* **Steps to Reproduce:**
  1. Open `/guest-check-in` at 320×568 viewport.
  2. Click `確認簽到` with empty inputs.
* **Expected Result:**
  Validation error appears inline above or adjacent to the invalid inputs without causing a disorienting full-page scroll jump.
* **Actual Result:**
  `<ScannerStatusOutput>` is located at line 361 of `attendance-panel.tsx`, rendered *below* the `<form>` and submit button ($y > 568\text{px}$). Because it renders below the viewport fold, an imperative `scrollIntoView({ block: "nearest" })` call triggers, scrolling the window down by 76px (`window.scrollY = 76`). This pushes the church branding header and top card boundary off the top of the screen.
* **Evidence:**
  * Screenshot: `docs/qa/screenshots/guest-320x568-validation-scroll.png`
  * Measurement: `scrollY: 76`, `output[data-tone="error"]` top $y = 498.3\text{px}$ (below submit button at $y = 442.3\text{px}$).
* **Contract-Safe Remediation:**
  Move `<ScannerStatusOutput>` inside the card header or directly above the form fields in `attendance-panel.tsx`, and remove the imperative `scrollIntoView` call so error feedback remains visible in the initial viewport.

### F-06: Quadruple repetition of title and hint text on manual code screen
* **Severity:** **Minor**
* **Surface:** `/scanner` (manual code entry screen)
* **Viewport:** 375×844, all viewports
* **Steps to Reproduce:**
  1. Open `/scanner` -> tap `停止掃描` -> tap `輸入代碼`.
  2. Inspect the rendered DOM hierarchy or navigate with screen reader (VoiceOver).
* **Expected Result:**
  Card presents a clear, non-repetitive heading and field label.
* **Actual Result:**
  The card renders:
  1. `h1` = "六位數代碼"
  2. `p.lead` = "輸入現場顯示的六位數代碼。"
  3. `span.fieldLabel` = "六位數代碼"
  4. `span.fieldHint` = "輸入現場顯示的六位數代碼。"
  VoiceOver reads the exact title twice and the exact sentence twice in immediate succession.
* **Evidence:**
  * Screenshot: `docs/qa/screenshots/scanner-manual-redundancy.png`
  * DOM Inspection: `self-check-in-panel.tsx:363-388` renders identical `{COPY.attendance.manualCodeLabel}` and `{COPY.attendance.manualCodeHint}` for both card header and form label/hint.
* **Contract-Safe Remediation:**
  In `self-check-in-panel.tsx:361-389`, when `withHeading` is true, omit the inner `span.fieldLabel` / `span.fieldHint` or let the `h1` serve as the accessible label via `aria-labelledby`.

### F-08: Copy-pasted guest code with surrounding whitespace causes resolution failure
* **Severity:** **Nit**
* **Surface:** `/guest-check-in`
* **Viewport:** 375×844, all viewports
* **Steps to Reproduce:**
  1. Copy a valid event code with leading/trailing spaces (e.g. from WhatsApp/SMS `" 482913 "`).
  2. Paste into `#attendance-code` on `/guest-check-in`.
  3. Fill name and phone, then click `確認簽到`.
* **Expected Result:**
  Form input is sanitized with `.trim()` before calling `resolve` RPC.
* **Actual Result:**
  If whitespace is passed directly to the resolver without trimming, the server search fails with `找不到此代碼對應的聚會`.
* **Evidence:**
  * Screenshot: `docs/qa/screenshots/hunt-paste-guest-untrimmed.png`
* **Contract-Safe Remediation:**
  In `attendance-panel.tsx:220`, pass `flow.input.trim()` to `flow.resolve()`.

## 4. Recommendations & Next Steps

### A. Immediate Fixes (Next Iteration / S3-06 Gate)
1. **Fix Compact-Phone Dock Collisions (F-01, F-02):**
   * Add `@media (max-height: 720px)` rules in `attendance-panel.module.css` to compact `.page` padding (`0.75rem 1rem`), `.confirmHeader`, and `.cameraStage` padding so both `停止掃描` and `不是這個聚會` sit comfortably above the floating dock ($y < 496\text{px}$ on 320×568; $y < 595\text{px}$ on 375×667).
2. **Fix Offline Retry Button Visibility (F-03):**
   * Update `self-check-in-panel.tsx:276` to ensure `retryAvailable` is set to `true` on retryable network errors so the `重試簽到` button renders as specified in F-11.
3. **Handle Stream Track Termination (F-04):**
   * Add `track.addEventListener("ended", ...)` in `use-qr-camera.ts` to transition immediately to the fallback view when hardware or OS permissions terminate the stream.
4. **Fix Guest Validation Layout Jump (F-05):**
   * Relocate `<ScannerStatusOutput>` in `attendance-panel.tsx` above or beside the form fields and remove the disorienting 76px scroll jump.
5. **Clean Up Desktop & Mobile Copy Redundancies (F-06, F-07, F-08):**
   * Hide `返回掃描` on desktop viewports (`isPhone && ...`).
   * Deduplicate `h1` and `fieldLabel` on the manual code screen.
   * Auto-trim `#attendance-code` on guest submission.

### B. Deferred Considerations (S7 Operator Alignment)
1. **Torch / Flashlight Control:** Gated by hardware detection; deferred per research note `2026-08-24-s3-checkin-ux-open-source.md` to avoid cluttering the one-bottom-action contract (F-18).
2. **Duplicate Check-In Timestamp:** Backend `duplicate` payload currently omits `attendance_id` and first-scan timestamp; defer timestamp display until S7 operator roster alignment.
