## 0. Environment model

One Cloudflare Worker origin (`web/wrangler.jsonc`) hosts the Next.js static export via the `ASSETS` binding (`web/worker.ts`: non-`/api` falls through to ASSETS) plus the `/api/v1/*` D1 surface: `auth/*` (sessions), `programs/*` (departments, programs, schedule rules, events, enrollment requests/decisions), and `attendance/*` (resolve, self, guest, operator roster/search/assisted, void, guest-correction).

The attendance suite targets the **shared dev-testing worker** `https://efcc-dev-testing.efcc-ggc.workers.dev` (same default and `PROGRAMS_TARGET_URL` override as the PRG-05 `programs-d1` suite; same six `PROGRAMS_*` role fixtures documented in `.github/CI-SECRETS.md`). The suite is browser-driven (real DOM) plus same-origin API assertions; every protected action is enforced server-side in the Worker, so the suite asserts server responses, never client-side gating alone.

## 2. Deployed suite design (`tests/e2e/attendance-d1.config.ts` + `attendance-d1.test.ts`)

- **Prereqs (secrets)**: the same six `PROGRAMS_*` role fixtures as `programs-d1` (`PROGRAMS_ADMIN_USERNAME`/`CREDENTIAL`, `PROGRAMS_STAFF_*`, `PROGRAMS_MEMBER_*`), all `E2E_`-prefixed. Config fails closed on a missing/non-HTTPS `PROGRAMS_TARGET_URL` and rejects hosts outside `efcc-auth-*.efcc-ggc.workers.dev` / `efcc-dev-*.efcc-ggc.workers.dev` (`PROGRAMS_ALLOW_LOCAL=1` opts into `http://localhost:*`).
- **Fixtures (API-only `beforeAll`, no browser)**: admin login → department (`E2E_ATT_*`) → enable `program_catalog`/`events`/`enrollment` modules → Recurring `MemberRequest` program (captures the 32-hex `check_in_token`) → WEEKLY rule on a never-today weekday → `events/generate` → three manual events whose check-in windows span "now" (A, B open; C cancelled via `PATCH .../events/:id {reason}`) → member enrollment request → admin `Approved`.
- **Check-in entry model** (verified against `web/lib/attendance.ts` `resolveEntryMethod`/`deriveCheckInMethod`): a typed entry is ambiguous — the server tries the Event `manual_check_in_code` first (migration 0004: 8 uppercase hex chars, globally unique), then the Program `check_in_token` (migration 0004: 32 lowercase hex chars). A member's personal `qr_code_string` (profile QR) is **not** a check-in entry in the D1 worker; the seeded `E2E-<ROLE>-<USER_ID>` values are exercised through the operator member search (exact `qr_code_string` match) and the profile QR surface.
- **Server gap fixed by this workstream** (root cause, required for the suite): API-created programs/events never received their check-in credentials — migration 0004 backfills existing rows only, and `d1-workspace-store` inserts omitted the columns. `createProgram` now mints `check_in_token = lower(hex(randomblob(16)))` and `createEvent`/`insertGeneratedEvent` mint `manual_check_in_code = upper(substr(hex(randomblob(4)), 1, 8))` plus the check-in window from the program's minutes-before/after config (same expressions as migration 0004). Without this, fresh fixtures resolve to nothing and every check-in is `CHECK_IN_CLOSED`/`CHECK_IN_NOT_FOUND`.

Determinism: each run starts from a clean D1 (reset deletes all `E2E_%` rows); fixtures are fresh per run (`E2E_ATT_*` department, fresh program/events); tests share only the immutable `beforeAll` fixtures and mutate only their own events/phones, so they are order-independent. `workers: 1`, `fullyParallel: false`, `trace: off` (credential request bodies must never be captured), 45 s per test.

## 3. Deploy / reset / seed procedure (operator steps, serialized with the shared worker)

```sh
# 1. Deploy this branch's worker to the shared dev-testing target (serialized
#    with the other workstream; migration 0004 auto-applies on deploy).
#    /tmp/wrangler-dev.json: worker name efcc-dev-testing, D1 id
#    edb464d2-d142-4c51-aa50-c5b800112756, migrations_dir web/migrations.
pnpm --dir web build
cp /tmp/wrangler-dev.json web/wrangler-dev.json
cd web && pnpm exec wrangler deploy --config wrangler-dev.json
rm web/wrangler-dev.json
#    Pre-flight: confirm the deployed Worker's RPC_RATE_LIMITER binding is
#    configured (guest check-in 503s without it).
#
# 2. Reset standing E2E_ rows so the run starts clean (idempotent). Use the
#    direct tsx binary (pnpm exec prints "Already up to date" to stdout and
#    corrupts redirected SQL) and a fresh filename per run (wrangler d1
#    execute caches by filename and replays stale content):
RESET=/tmp/att-reset-$(date +%s%N).sql
./node_modules/.bin/tsx tests/e2e/seed-dev-accounts.ts --reset > "$RESET"
pnpm exec wrangler d1 execute efcc-dev-testing --remote --file="$RESET"
#
# 3. Seed the three E2E_ dev accounts WITH qr_code_string. The seed is
#    INSERT OR IGNORE: rows seeded earlier (pre-fix, no qr_code_string)
#    would survive untouched, so delete them first, then seed, then verify:
SEED=/tmp/att-seed-$(date +%s%N).sql
./node_modules/.bin/tsx tests/e2e/seed-dev-accounts.ts > "$SEED"
pnpm exec wrangler d1 execute efcc-dev-testing --remote \
  --command="DELETE FROM accounts WHERE user_id IN ('U-E2E-ADMIN','U-E2E-STAFF','U-E2E-MEMBER');"
pnpm exec wrangler d1 execute efcc-dev-testing --remote --file="$SEED"
pnpm exec wrangler d1 execute efcc-dev-testing --remote \
  --command="SELECT user_id, role, qr_code_string FROM accounts WHERE user_id LIKE 'U-E2E-%';"
#    Expect E2E-ADMIN-U-E2E-ADMIN / E2E-STAFF-U-E2E-STAFF / E2E-MEMBER-U-E2E-MEMBER.
#
# 4. Run the suite (defaults to https://efcc-dev-testing.efcc-ggc.workers.dev).
#    Fixtures (department/program/events/enrollment) are rebuilt inside the
#    run by test.beforeAll, AFTER the reset in step 2, so a stale E2E_ state
#    can never leak into the run:
PROGRAMS_ADMIN_USERNAME=... PROGRAMS_ADMIN_CREDENTIAL=... \
PROGRAMS_STAFF_USERNAME=... PROGRAMS_STAFF_CREDENTIAL=... \
PROGRAMS_MEMBER_USERNAME=... PROGRAMS_MEMBER_CREDENTIAL=... \
pnpm exec playwright test --config=tests/e2e/attendance-d1.config.ts
#
# 5. Append evidence to this doc:
pnpm exec tsx tests/e2e/plan-doc-appender.ts \
  --plan=docs/omp-plans/2026-08-07-att-04-ticket-216.md \
  --results=test-results/attendance-d1-results.json \
  --heading="## Executed results" \
  --target-url=https://efcc-dev-testing.efcc-ggc.workers.dev
```

`PROGRAMS_ALLOW_LOCAL=1` + `PROGRAMS_TARGET_URL=http://localhost:8787` runs the same suite against `wrangler dev` for local pre-flight.

### Product bugs the suite caught (fixed in `web/lib/attendance.ts`, regression-tested)

1. **Bare-entry check-in always 403'd** (`deriveCheckInMethod`): the final
   `eventMatchesEntry` re-check passed `input.manual_code`/`input.program_token`
   — both undefined for entry-only submits — so the panel's primary typed-entry
   flow could never check in. The resolved entry is now used as the credential
   for the resolved method. Unit coverage: `attendance-worker.test.ts`
   "bare typed entry resolves and checks in…".
2. **Cancelled Event's manual code 404'd instead of 410** (`handleResolve`): the
   entry fallback flipped `matchedToken` unconditionally, so the status lookup
   searched the Program-token column for a manual code. The entry path now
   checks the manual column's status first, then the token column (same order
   as `resolveEntryMethod`). Unit coverage: "entry status lookup: cancelled
   manual code 410s, closed manual code 409s".
