## Acceptance criteria

### EVT-02.1 — Preview is exact and non-mutating

- Create or edit weekly and monthly recurring rules with explicit Hong Kong wall-clock time, location, horizon, and boundary dates.
- Add a cancel exception and a reschedule exception.
- Choose **Preview** from the reachable workspace.
- The response/DOM shows a server-owned plan identity and exact occurrence rows: local date, local time, location, source rule, and exception/skip state.
- Before and after preview, the observable event directory contains the same rows and the audit stream contains no generation success or created-event records.
- Zero schedule rules produces an explicit failed response and failed audit record; it does not silently return an empty successful plan.

### EVT-02.2 — Plan identity prevents stale writes

- Preview the current rules and record the plan identity/hash.
- Change a rule or exception, then attempt to generate with the old plan.
- The response is a deterministic stale-plan error; no event is written and the UI refreshes or requires a new preview.
- Repeating Preview without changing inputs returns the same occurrence ordering and plan identity.

### EVT-02.3 — Generation is authorized, idempotent, and auditable

- Generate from a current valid preview as the authorized Manager/Program Leader.
- The event directory shows only occurrences authorized by the current plan, with shared event detail links.
- Repeating the same generation is deterministic: no duplicate event rows, explicit created/skipped counts, and an audit/generation-run record.
- A user without Program Manage or outside the program scope receives a forbidden result and creates neither events nor generation records.

### EVT-02.4 — Recovery and concurrency are safe

- Exercise retry after a generation run has recorded a partial/failed unit. Retry resumes from durable run state and never duplicates already-created events.
- Start two equivalent generation attempts concurrently. At most one event exists for each unique program/start pair; both responses expose deterministic created/skipped or conflict outcomes.
- A malformed/ambiguous preview is rejected before event writes and leaves the event directory unchanged.

### EVT-02.5 — Reachability and accessibility

- All controls above are reachable from the current Program Workspace in the browser without navigating through the legacy manager.
- Loading, empty, error, stale, forbidden, and success states are visible in the DOM with accessible names and keyboard operation.
- The shared event directory and event detail remain usable at narrow viewport widths.

### Review-fix follow-up (applied on top of the first implementation commit)

Commit: `HEAD` of `feat/recurring-event-generation-252` (second commit, see `git log`).

Addresses the two-axis review findings:

1. Migration renamed to `0008_event_preview_generation.sql` (base `b7f18427` already ships
   `0007_department_managers.sql`); local application confirmed by the workerd vitest pool
   (`applyMigrations` applies 0000–0008 in order — 124/124 worker tests pass on the migrated schema).
2. All preview/run FKs now `ON DELETE RESTRICT` (no CASCADE/SET NULL): deleting an exception,
   rule, or plan can never silently erase durable preview/run evidence. `exception_id` on preview
   occurrences is snapshot attribution without an FK, so the preserved trunk “restore exception”
   flow keeps working while stale plans remain and are rejected at generation (409 STALE_PLAN).
3. Preview exception selection is rule-scoped (`rule_id + override_date` keyed); same-date
   exceptions on one rule never cross-affect another rule — regression test added.
4. Repeated completed generation emits its own `EVENT_GENERATE` SUCCESS audit with
   created=0/skipped>0 (ADR-0027); stale/empty-plan business conflicts audit `CONFLICT`, not
   FAILED; zero-rule preview keeps FAILED.
5. Generation attribution: after an ignored `INSERT OR IGNORE`, the attempt verifies the event
   row actually exists — a genuine duplicate records `skipped` WITH the existing event_id; any
   other swallowed constraint records `failed`, never a false skip. `event_id` on run items is a
   plain index (the same event is legitimately referenced by its creating run and later skipped
   runs). `finishGenerationRun` now settles counts/status atomically from the item table with a
   `finished_at IS NULL` compare-and-set; every caller reloads the settled row so the run and all
   responses converge.
6. Rule `location` clearing persists (explicit null is distinguished from absent via a sentinel
   CASE), and malformed non-string location fails closed with 422 — regression tests added.
7. Preview DTO projects `created_by` out (`PreviewPlanView`); `EmptyPreviewPlanError` is
   generic (no plan UUID leak).

### Seed reset regression fix (committed follow-up)

`pnpm db:seed:local` (checked-in `tests/e2e/seed-dev-accounts.ts --reset`) previously
failed with `FOREIGN KEY constraint failed` once EVT-02 preview/run rows existed, because
the reset deleted programs/rules/events (parents) before the new RESTRICT children. Fixed
by deleting the EVT-02 tables first, children before parents:

1. `program_generation_run_items` (scoped via runs of `E2E_*` programs)
2. `program_generation_runs`
3. `program_preview_occurrences`
4. `program_preview_plans`

then the existing exceptions/rules/attendances/events/enrollments/requests/leaders/
programs/modules/managers/departments/registration-requests deletes. RESTRICT is
unchanged. Verified against a local D1 that held real EVT-02 plans/runs/items from the
Playwright run: `pnpm db:seed:local` now succeeds and leaves plans/runs/items/
occurrences/programs/events all at 0. Added worker regression `EVT-02.6 checked-in seed
reset order clears preview/run rows before their parents` (replays the reset statements
verbatim against the schema and asserts the E2E_ program and all durable rows are gone).
