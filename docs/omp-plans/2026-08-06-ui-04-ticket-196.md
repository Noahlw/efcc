## 1. Backend RPC contract

### 1.1 `POST /api/v1/auth/username` — body `{ username }`

| # | Acceptance criterion | Assertion method (worker contract test) |
|---|---|---|
| U1 | Session-authenticated (access cookie); no current password required | `worker.fetch` with valid access cookie → 200; missing/invalid cookie → 401 |
| U2 | Success `200 { requestId, data: { username, sessionRevoked: true } }`; new display username echoed | parse body, assert `data.username`, `data.sessionRevoked === true`, `requestId` === `X-Request-Id` |
| U3 | Both auth cookies cleared via real `Set-Cookie` delete headers | `res.headers.getSetCookie()` contains `efcc_access=; ... Max-Age=0` and `efcc_refresh=; ... Max-Age=0` |
| U4 | `username` empty after trim → `422 VALIDATION` `username is required` | call with `""` / `"   "` → assert 422, `code === "VALIDATION"` |
| U5 | Malformed body → `422 VALIDATION` | non-JSON body → 422 |
| U6 | Duplicate (casing/whitespace variant against `accounts`) → `409 CONFLICT` `An account with that username already exists`, **no mutation** | assert 409; assert `accounts` row for actor unchanged; no `account_events` row; sessions not revoked |
| U7 | Duplicate against `registration_requests` → `409 CONFLICT`, no mutation | seed pending registration with the target username; assert 409 + no mutation |
| U8 | Race fail-closed: concurrent insert wins → batch aborts → `409` | (unit) assert the batched uniqueness constraint path returns 409 on a unique-index violation |
| U9 | Unchanged value → `200` value-idempotent no-op; no audit row; no session revocation; `sessionRevoked: false` | submit actor's own current username → 200, no new `account_events` row, sessions still active, `data.sessionRevoked === false` |
| U10 | `User_ID` unchanged; QR identity default unchanged | assert `accounts.user_id` and `qr_code_string` unchanged after username change |
| U11 | Account not `Active` → `403` | seed a `Pending`/`Suspended` account with a valid session → 403 |
| U12 | Audit row `username_changed` written with old/new normalized usernames, `correlation_id = requestId`; no credential material | read `account_events`; assert action, both normalized values, correlation_id; assert no `password`/`hash`/`token`/`session` key or value in the row |
| U13 | All refresh sessions for the account revoked inside the transaction | count `sessions` with `revoked_at IS NULL` for actor → 0 after success |

### 1.2 `POST /api/v1/auth/password` — body `{ currentPassword, newPassword }`

| # | Acceptance criterion | Assertion method (worker contract test) |
|---|---|---|
| P1 | Session-authenticated; missing/invalid session → `401` | worker.fetch with/without cookie |
| P2 | Success `200 { requestId, data: { sessionRevoked: true } }` + both cookies cleared | assert body + Set-Cookie delete headers |
| P3 | Wrong `currentPassword` → `422 VALIDATION` `current password is incorrect` (NOT 401) | submit wrong current → 422, `code === "VALIDATION"`, `detail` includes `current password is incorrect` |
| P4 | Wrong current → **no audit row, no revocation** | assert zero new `account_events` rows; sessions still active |
| P5 | `newPassword` < 8 chars → `422 VALIDATION` | submit 7-char new → 422 |
| P6 | `newPassword` ≥8 chars (Unicode) accepted | submit an 8+ char password with non-ASCII characters → 200 |
| P7 | New credential hash stored; old credential unusable | assert `credential_hash` changed and verifies against new password; `credential_kind === 'password'` |
| P8 | Audit row `password_changed` (no username columns, no credential material) | read `account_events`; assert action, `old/new_username_normalized IS NULL`, no credential material |
| P9 | All refresh sessions revoked | active session count → 0 |
| P10 | Missing field → `422 VALIDATION` | omit `currentPassword` or `newPassword` → 422 |
