## 1. RPC contract — Schedule rules

| # | Criterion | Assertion method (worker contract test) |
|---|---|---|
| R1 | `POST /api/v1/programs/:id/schedule-rules` creates a rule when actor has `program.manage` for that program; Member/outsider → `403 FORBIDDEN` | Admin/Staff/ProgramLeader with grant → `201 { requestId, data: { rule } }`; Member → `403` |
| R2 | Body contract: `recurrence` (`WEEKLY\|MONTHLY`), `start_time`/`end_time` `HH:MM` (24h), `day_of_week` 0–6 required for WEEKLY, `month_day` 1–31 required for MONTHLY; end_time > start_time | invalid enum/time/missing day → `422 VALIDATION`; no rule row written |
| R3 | Rule creation is rejected (`422`) when the program's `behavior_type` is `OneOff` | create rule under OneOff program → `422` |
| R4 | `PATCH /api/v1/programs/:id/schedule-rules/:ruleId` edits the rule without touching any existing Event occurrence | generate → PATCH rule (times/days) → assert all pre-existing `events` rows byte-identical (id, starts_at, ends_at, status) |
| R5 | All rule mutations are audited in `audit_events` (`entity_type='schedule_rule'`, `action` `SCHEDULE_RULE_CREATE`/`SCHEDULE_RULE_UPDATE`, `correlation_id = requestId`) | read `audit_events`, assert action/entity/snapshots/correlation |
| R6 | Unknown rule/program → clean `404 NOT_FOUND` | random UUID → `404` |

## 2. RPC contract — Occurrence generation

| # | Criterion | Assertion method |
|---|---|---|
| G1 | `POST /api/v1/programs/:id/events/generate` materializes concrete `events` rows (source `SCHEDULE`) for every rule of a `Recurring` program, for the default 90-day horizon from today in `Asia/Hong_Kong` | seed WEEKLY rule (e.g. Tue 19:30) → generate → assert N rows, each `starts_at` = the correct UTC instant for HK wall time, `status='Active'`, `source='SCHEDULE'` |
| G2 | Weekday/monthday matching is computed in `Asia/Hong_Kong` wall calendar, not UTC | rule day_of_week that is a different weekday in UTC than in HK still lands on the HK weekday |
| G3 | Generation is idempotent and duplicate-safe | run generate twice → second run returns `{ created: 0, skipped: N }`; row count unchanged (UNIQUE `(program_id, starts_at)` + INSERT OR IGNORE) |
| G4 | Exceptions apply per occurrence: `POST /api/v1/programs/:id/schedule-rules/:ruleId/exceptions` with `action=CANCEL` (`override_date`) suppresses that occurrence; `action=RESCHEDULE` with `new_start_time`/`new_end_time` moves it | cancel one date → generate → no event on that date, others intact; reschedule a date → event exists with the new wall time converted to UTC |
| G5 | `DELETE /api/v1/programs/:id/schedule-rules/:ruleId/exceptions/:exceptionId` removes an exception | after delete + regenerate, the occurrence reappears |
| G6 | Generation for a `OneOff` program → `422` (no rules to generate) | assert clean `422` |
| G7 | Generation run is audited once (`EVENT_GENERATE`, `new_value_json` = `{ created, skipped, rule_count }`) | assert single audit row with counts |
| G8 | Cancelling an exception is audited; unknown exception → `404` | assert audit row; random UUID → `404` |

## 3. RPC contract — Events (manual + lifecycle)

| # | Criterion | Assertion method |
|---|---|---|
| E1 | `POST /api/v1/programs/:id/events` creates a manual event (`source='MANUAL'`) — the OneOff path — for an authorized manager | OneOff program → `201`, row has source `MANUAL`, correct `starts_at`/`ends_at` (ISO-8601 UTC) |
| E2 | Validation: `starts_at`/`ends_at` required ISO-8601, `ends_at > starts_at`; duplicate `(program_id, starts_at)` → `409 CONFLICT` | invalid body → `422`; duplicate start → `409`, no second row |
| E3 | `GET /api/v1/programs/:id/events` lists events ordered by `starts_at`; managers see all statuses, Members see `Active` events only of visible programs | assert order; Member request on Unlisted program → only Active/`Listed`-visible subset |
| E4 | `PATCH /api/v1/programs/:id/events/:eventId` `{ reason }` performs a **soft** cancel: `status='Cancelled'`, `cancel_reason` set, `updated_by`/`updated_at` recorded | assert row after PATCH |
| E5 | Cancellation is audited (`EVENT_CANCEL`, `entity_type='event'`, old/new snapshots, `correlation_id`) | assert `audit_events` row |
| E6 | Cancellation preserves historical Attendance relationships | seed an `attendances` row for the event → cancel → attendance row unchanged (`status='Active'`, same `checked_in_at`) |
| E7 | Cancel with empty reason → `422`; unknown event → `404`; unauthorized → `403` | assert each |
| E8 | No credential material in any response body | assert absence of `password`/`hash`/`token`/`session` keys/values |
