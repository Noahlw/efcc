## 1. Schema / migration contract

| # | Acceptance criterion | Assertion method (worker contract test / schema introspection) |
|---|---|---|
| M1 | Migration `0002_d1_program_domain.sql` applies cleanly on top of `0000_init.sql` + `0001_account_events.sql` | `applyMigrations()` succeeds; `__d1_migrations` records all three |
| M2 | New tables exist: `role_capabilities`, `departments`, `department_modules`, `programs`, `program_schedule_rules`, `program_schedule_exceptions`, `events`, `enrollment_requests`, `enrollments`, `program_leaders`, `attendances`, `audit_events` | `PRAGMA table_info(...)` asserts required columns |
| M3 | All new tables use `TEXT` UUID PKs and `STRICT` mode | introspection query |
| M4 | All closed vocabularies are `CHECK`-constrained (`lifecycle`, `behavior_type`, `discoverability`, `enrollment_mode`, `status`, `source`, `outcome`, etc.) | invalid INSERT aborts with CHECK constraint failure |
| M5 | Foreign keys are `ON DELETE RESTRICT` and enforced; local test harness sets `PRAGMA foreign_keys = on` | `DELETE FROM accounts` while referenced row exists → FK violation; orphan insert into `programs` with bad `department_id` → FK violation |
| M6 | Partial unique indexes enforce at-most-one active relationships: `enrollments(program_id, member_user_id) WHERE status='Active'`, `program_leaders(program_id, user_id) WHERE revoked_at IS NULL`, `attendances(event_id, member_user_id) WHERE status='Active'` | duplicate active insert → unique-index violation |
| M7 | `audit_events` is immutable via triggers (`audit_events_no_update`, `audit_events_no_delete`) | UPDATE/DELETE on `audit_events` → `RAISE(ABORT, ...)` |
| M8 | Existing identity tables receive backfilled `CHECK` constraints on `account_status`, `role`, `credential_kind` (§10.2) | invalid `role='Foo'` / `account_status='Foo'` insert → CHECK failure |
| M9 | Indexes from §11 are present: `programs_department_idx`, `schedule_rules_program_idx`, `schedule_exceptions_rule_idx`, `events_program_start_idx`, `enrollment_requests_program_status_idx`, `enrollment_requests_member_idx`, `enrollments_member_idx`, `attendances_event_idx`, `audit_events_entity_idx`, `audit_events_actor_idx`, `audit_events_corr_idx` | introspection |

## 2. Backend RPC contract — Departments

| # | Criterion | Assertion method (worker contract test) |
|---|---|---|
| D1 | `POST /api/v1/programs/departments` creates a department when actor has `department.manage` capability | Admin/Staff caller → `201 { requestId, data: { department } }`; Member/ProgramLeader-only → `403 FORBIDDEN` |
| D2 | Required fields: `code` (unique), `name`, `lifecycle` (`Draft\|PendingDevelopment\|Active\|Archived`); `description` optional | missing/invalid → `422 VALIDATION` |
| D3 | Duplicate `code` fails closed with `409 CONFLICT` | create same code twice → second `409` and no duplicate row |
| D4 | `GET /api/v1/programs/departments` lists departments with metadata, ordered by `display_order` then `created_at` | assert array shape, `department_id`, `code`, `name`, `lifecycle`, `display_order` |
| D5 | `GET /api/v1/programs/departments/:id` returns single department or `404 NOT_FOUND` | existing → `200`; random UUID → `404` |
| D6 | `PATCH /api/v1/programs/departments/:id` updates name/description/lifecycle/display_order for authorized actor | assert `200`, row updated, `updated_by` = caller, `updated_at` set |
| D7 | Department lifecycle publish to `Active` requires `department.publish` capability; Admin/Staff may publish, Member/ProgramLeader may not | `PATCH { lifecycle: "Active" }` with Staff → `200`; with Member → `403` |
| D8 | All department mutations are audited in `audit_events` with `entity_type='department'`, `entity_id`, `actor_user_id`, `action` (`DEPARTMENT_CREATE` / `DEPARTMENT_UPDATE`), `outcome`, old/new snapshots, `correlation_id = requestId`; no credential material | read `audit_events` and assert |

## 3. Backend RPC contract — Programs

| # | Criterion | Assertion method (worker contract test) |
|---|---|---|
| P1 | `POST /api/v1/programs/departments/:id/programs` creates a program under a department when actor has `program.manage` for that department | Admin/Staff/ProgramLeader with grant → `201`; Member → `403` |
| P2 | Required fields: `name`, `behavior_type` (`Recurring\|OneOff`), `lifecycle` (`Draft\|Active\|Archived`), `discoverability` (`Listed\|Unlisted`), `enrollment_mode` (`MemberRequest\|ManagerOnly`); `category`/`description` optional | invalid enum → `422` |
| P3 | Program lifecycle publish to `Active` requires `program.publish` capability | Staff → `200`; unauthorized → `403` |
| P4 | `GET /api/v1/programs/departments/:id/programs` lists programs for a department, respecting `Listed`/`Unlisted` authorization: `Unlisted` visible only to managers/publishers; `Listed` visible to all authenticated users | Member sees only `Listed` programs; manager sees all |
| P5 | `GET /api/v1/programs/:id` returns program or `404` | assert shape |
| P6 | `PATCH /api/v1/programs/:id` updates program fields for authorized actor | assert row updated and audit row written |
| P7 | Invalid `department_id` reference → `404 NOT_FOUND` (or FK failure mapped to 404) | assert no server crash, clean 404 |
| P8 | Program mutations audited in `audit_events` with `entity_type='program'` | assert action, outcome, snapshots, correlation_id |

## 5. Authorization seam contract

| # | Criterion | Assertion method |
|---|---|---|
| A1 | `CapabilityAuthorizer` resolves global role policy from `role_capabilities`; absent policy defaults to a conservative deny | seeded Admin/Staff policies grant capabilities; Member policy has no management capabilities |
| A2 | Department/Program scope checks route through authorizer; a Program Leader grant (`program_leaders`) grants `program.manage` only for that program | leader of program A can manage A, not B |
| A3 | Browser visibility is never authority: a direct `POST` from a Member actor is rejected even if the UI would not have shown the button | worker test with forged cookie |
| A4 | Role hierarchy preserved: Admin can edit any role's policy; Staff can edit Member policy only; Member cannot edit policies (deferred to PRG-05, but deny is asserted here) | policy-edit routes reject lower roles |
