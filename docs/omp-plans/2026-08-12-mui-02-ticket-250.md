# MUI-02 (#250) — Scoped Program management acceptance trace

**Date:** 2026-08-12
**Worktree:** `feat/program-management-250`, based on `9b9110f0`
**Scope:** Recurring/OneOff Program create, edit, activate, archive flows and their Management Directory/Program Workspace entry points. Event, schedule-generation, enrollment, settings-group, leader, and notification workflows remain owned by sibling tickets.

This trace is written before implementation. The public seams are the cookie-only Worker routes and the rendered Management Directory/Program Workspace/form DOM; D1 assertions cover durable audit and historical-row invariants.

| Criterion | Observable proof |
|---|---|
| Authorized operators create only in permitted Departments | Worker contract: scoped capability allows create; Member and unrelated Program-only/scope actor receives `403 FORBIDDEN`; no Program row is written. |
| Creation captures required identity, category, behavior, lifecycle, discoverability, enrollment mode without unrelated settings | Worker contract asserts complete safe response values and rejects missing/unknown fields; component form exposes only the requested Program fields. |
| OneOff supports multiple independently operated Events | Existing Event API/domain remains usable for multiple manual events; Program form does not add a single-occurrence constraint; contract regression exercises two distinct event starts. |
| Edit/activate returns to resulting Workspace with confirmed values and clear outcomes | Component form submits, reloads `getManagementProgram`, and preserves Workspace route; tests cover success, `CONFLICT`, `VALIDATION`, `FORBIDDEN`, and network/ambiguous transport copy/recovery. |
| Archive rejects unresolved future commitments while preserving evidence | Worker/domain contract creates future Active Event and/or Pending Enrollment request, attempts archive, asserts `409 PROGRAM_ARCHIVE_BLOCKED` and unchanged lifecycle; after commitments are resolved, archive succeeds and historical Event/Enrollment/Attendance rows remain. |
| Lifecycle is Draft -> Active -> Archived | Domain transition tests reject reverse/skipped transitions; no event-date/availability inference is introduced. |
| D1 mutation/audit, capability, form recovery, component, and E2E coverage | Focused Worker/domain tests, form/component tests, and local Playwright acceptance run against `wrangler dev` + disposable `E2E_`/`E2E_DEMO_` fixtures. |

**Assumptions:** the existing PATCH Program route is the lifecycle mutation seam; archive constraints use established domain rows (`events.status = Active` with a future `starts_at`, and `enrollment_requests.status = Pending`). Historical rows are never deleted or rewritten.
