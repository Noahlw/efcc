| 260-2 | Full guest contact data is visible only to capabilities approved by the attendance privacy contract; ordinary Members and cross-scope operators receive no leakage | Worker contract tests for Member and cross-scope operator token denial; response payloads contain zero contact data fields (`guest_name`, `guest_phone`, `guest_phone_normalized`, `attendances`) |

| 260-4 | Incorrect check-in is voided rather than deleted; repeat void, duplicate phone, and validation error outcomes remain deterministic | Worker/D1 tests assert `status = 'Voided'`, `void_reason`, `voided_by`, `voided_at`, repeat void returns 200 `{ outcome: "already_voided" }` with `DUPLICATE`/`ALREADY_VOIDED` audit log, and blank reason is rejected with 422 `VALIDATION` |
| 260-5 | A Voided record releases only the domain-approved active duplicate slot and never rewrites Enrollment or unrelated Attendance history | D1 test confirms voided guest phone can check in again (releasing partial unique index), and exact Enrollment rows and unrelated Attendance rows remain identical before vs after void |

| 260-7 | Privacy, audit, correction/void, capability, component, accessibility, and deployed end-to-end tests cover Member and Guest records | Vitest unit/component suites, Worker/D1 contract tests, and local Playwright E2E suite |
