## Public seams

- Existing `ProgramsIntent` and `ParticipantProgramDetail` remain the URL/detail authority; enrollment UI is nested in the participant detail and does not add a second route or manager workspace.
- Existing cookie-only `submitEnrollmentRequest`, `listEnrollmentRequests`, `withdrawEnrollmentRequest`, `listEnrollments`, and `cancelEnrollment` APIs remain the transport seams. `programsFetch` continues to mint `Idempotency-Key` for POST and surface RFC ProblemDetails as `RpcError`.
- Existing `DepartmentWorkspace`/D1 store enforce module, capability, MemberRequest/ManagerOnly mode, ownership, active-enrollment, audit, and conflict semantics. The new partial unique Pending-request index is the database race guard; the UI never substitutes for it.
- All participant responses remain narrow: no check-in secrets, operator/member queue breadth, leader controls, or manager decisions cross the participant detail boundary. Copy stays in `web/lib/copy.ts`; CSS reuses Civic Minimal tokens and 44px controls.
