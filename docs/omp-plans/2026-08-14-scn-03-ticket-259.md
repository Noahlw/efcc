**Date:** 2026-08-14
**Worktree:** `feat/guest-checkin-259` (stacked on `feat/scanner-assisted-258` @ `ede57916`)
**Spec authority:** Issues #241, #244, #249, #257, #258, #259; ADR-0018 (HTTP boundary/RFC 9457), ADR-0020 (cookie-only auth transport), ADR-0023 (single-lock mutation/audit), ADR-0026 (D1 domain schema), ADR-0027 (audit outcomes), ADR-0028 (public civic landing surface), ADR-0029 (local-first readiness gate).
**Scope:** Deliver public Guest Check-In on `/guest-check-in` and the signed-out landing page. Visitors identify an eligible Event by Program QR or manual code, provide required guest details (name + normalized phone), and record attendance without creating a Session, Account, or Enrollment record. Choosing login mid-flow preserves the pending Check-In Credential across the authenticated login transition, landing the user on `/scanner` in Self mode with the Event context prefilled for explicit member check-in. #260 attendance roster, correction, void, privacy, and audit completion are deferred.

> The local `wrangler dev` + disposable D1 browser run is the required READY gate under ADR-0029. Physical camera smoke is manual evidence only; no device/deployment result may be fabricated.
