# Domain docs

EFCC is one church-management product and one domain context, even though the repository has root tooling and a web application.

## Before domain work

- Read root CONTEXT.md for canonical terms and domain invariants.
- Read only the accepted or superseded ADR decisions relevant to the change in docs/adr/.
- Keep implementation plans and handoffs in docs/plans/; keep CONTEXT.md focused on domain language and invariants.
- Record a new durable decision in a new ADR. Preserve prior decisions and link superseding records instead of rewriting history.

The canonical layout is one root CONTEXT.md plus root docs/adr/; this repository does not use CONTEXT-MAP.md or context-local ADR folders.
