# #646 non-Auth route matrix

Source: apps/web/worker.ts at the #646 branch. Each row is one dispatched method/path, including action alternatives expanded from regex routes. There are 88 rows: Home 7, Identity 13, Programs read/feed 18, settings 10, schedule/events 13, enrollment 13, Attendance 14. A route's handler remains the authority for exact status, permission, optional/nullable fields, and extra-field policy. This matrix records the boundary to verify; a listed seam is not a passing test result.

All successful JSON rows use the {requestId,data} envelope and the named shared data schema family. All failures remain non-2xx RFC 9457 Problem Details with HTTP status and X-Request-Id; malformed error bodies use UNAVAILABLE. Unless marked otherwise, unrecognized query/body fields retain the handler's existing ignore behavior and are never silently stripped from a response. Request codes: p = path ID, q = query, b = JSON body, h = Idempotency-Key/correlation header, c = existing clamped query, v = existing strict or conditional validation, — = no consumed request field. Actor codes: U = public or optional session, M = Active member, G = Active account with handler-scoped management filtering or authorization, R = Active account plus Role/Grant authority, C = Active account plus HOME_PUBLISH, O = Active authorized Attendance operator. Mutation codes: — = read, audit = existing requestId/correlation with the handler's current outcome, key = client Idempotency-Key correlation with the handler's current outcome, proof = guest proof-bound reconciliation. A key row does not imply Worker deduplication unless its handler implements it. Client/seam codes: H = home-api/Home browser, HC = home-cms-api/CMS browser, I = Identity client/Worker contract, P = program-api/Programs browser, N = notices-api/Worker contract, A = Attendance client/Worker contract and critical browser journey, W = Worker contract only.
