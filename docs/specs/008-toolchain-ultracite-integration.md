# Specification: Integrate Ultracite (Oxlint + Oxfmt) into the EFCC Webapp Toolchain

**Status**: ready-for-agent
**Date**: 2026-07-28
**Context**: 顯恩堂系統 — EFCC Church Management System (TypeScript WebApp)
**Origin**: Grilling session 2026-07-28 against `/Users/noah.wong/Desktop/code/EFCC-dev`

---

## Problem Statement

The EFCC webapp (`src/frontend` workspace) currently relies on a single-tool formatting setup:

- Root `package.json` declares `prettier ^3.6.2` as the only formatting devDependency.
- A single repo-wide Prettier config block sits in the root `package.json` (`useTabs: false`, `tabWidth: 2`, `printWidth: 80`, `singleQuote: false`, `trailingComma: "es5"`, `semi: true`, `arrowParens: "always"`).
- `.husky/pre-commit` triggers `lint-staged`, which runs `prettier --ignore-unknown --write` against every staged file.
- No ESLint, no Biome, no Oxlint/Oxfmt, no Stylelint are installed.

This produces three concrete limitations as the project grows:

1. **No lint coverage at all.** Prettier formats whitespace and nothing else. The codebase has no automatic guard against unused imports, missing hook dependencies, accidental `any`, or React rule violations like missing `key` props.
2. **Toolchain bloat the wrong direction.** The natural next step is to add ESLint, which adds at least three packages (`eslint`, a config, a React plugin), a parser, and a TypeScript resolver — ~6 devDependencies — for a project that otherwise has no JavaScript toolchain debt.
3. **AI-coding-session drift.** Recent OMP memory shows multiple agents touching this repo (PR #151 work, EFCC migration planning, an interactive hooks picker, a spec ticket workflow). Without a linter enforced pre-commit, formatting and rule adherence drift across agents.

The fix: swap the existing Prettier-only pipeline for **Ultracite** with the **Oxlint + Oxfmt** engine stack. This replaces one tool with three peers (`ultracite`, `oxlint`, `oxfmt`), adds lint coverage, and keeps the pre-commit path a single command. No ESLint, no Stylelint, no Babel — Rust tools only.

---

## Solution

Adopt Ultracite as the unified formatter + linter for the EFCC monorepo, engine set to **Oxlint + Oxfmt**. Ultracite supplies the curated rule preset; Oxlint handles linting and Oxfmt handles formatting. Both run through a single `ultracite fix` or `ultracite check` wrapper so the pre-commit pipeline stays one call.

The migration is a single atomic commit group consisting of:

1. **Tool swap** (root `package.json`):
   - Remove `prettier` devDependency.
   - Remove the root `prettier` config block.
   - Add `ultracite`, `oxlint`, `oxfmt` as root devDependencies, pinned to the resolved versions from this spec.
2. **Pre-commit repoint** (root `package.json` `lint-staged`):
   - Replace the single `"*": "prettier --ignore-unknown --write"` rule with `"*": "ultracite fix"` (or a narrower glob scoped to the workspace's source, decided at implementation time based on `ultracite fix`'s file-type acceptance on this tree).
3. **Editor wiring** (`.vscode/settings.json`):
   - Generated by `npx ultracite init --editors universal`. Must reference the Oxc VS Code extension (or whatever formatter ID the pinned Ultracite 7.9.4 template writes) — **must not reference the Prettier extension**.
4. **Engine config files**:
   - `oxfmt.config.js` (or `.oxfmtrc.json` — whichever the Ultracite 7.9.4 init template writes) at repo root.
   - `oxlint.config.js` (or equivalent) at repo root.
5. **One autofix commit** containing the formatted + safe-fixed diff. Existing violations become part of the same atomic migration so the post-migration `ultracite check` exits 0.

Toolchain-bound versions (from the npm registry, not from documentation):

| Package | Version | Role |
|---|---|---|
| `ultracite` | `7.9.4` | Preset + CLI wrapper (`init`/`check`/`fix`/`doctor`) |
| `oxlint` | `1.76.0` | Linter binary |
| `oxfmt` | `0.61.0` | Formatter binary |

`ultracite` lists `oxlint` and `oxfmt` as **optional peerDependencies**. They are not transitive. The repo must install them explicitly, which is part of this migration.

## User Stories

1. As a developer committing to `efcc`, I want the pre-commit hook to enforce both formatting and lint rules, so I cannot push code that violates the preset.
2. As a developer opening `efcc` in VS Code or Cursor, I want format-on-save wired to the same engine as the pre-commit hook, so what I save locally matches what CI runs.
3. As an OMP coding agent editing files in `efcc`, I want the lint/format config visible in `oxlint.config.js` / `oxfmt.config.js`, so I can read it before generating code instead of guessing.
4. As a reviewer reviewing a PR against `main`, I want `npx ultracite check` to be a single command that exits clean, so the lint status of the tree is one operation.
5. As a maintainer extending the preset, I want `npx ultracite doctor` to validate the install, so a half-wired configuration surfaces immediately rather than at commit time.
6. As a future contributor, I want the spec to record which engine versions and which Ultracite CLI flags were used, so I can reproduce the migration on a fork or after a major upgrade.

## Implementation Decisions

### Engine choice — Oxlint + Oxfmt

- **Why Oxlint + Oxfmt**: matches Ultracite's current documented default and uses the Rust-based Oxc stack. Single-binary per role; faster than ESLint on lint; matures faster than Biome on lint-ecosystem.
- **Why not Biome**: Biome is a single-tool option with a comparable preset. The Oxc stack is what Ultracite's own docs and CLI defaults promote as of v7.9.4. Picking the documented default defers engine choice to the upstream project's own judgment.
- **Why not ESLint + Prettier + Stylelint**: heavier (6+ packages), slower, and reintroduces the toolchain bloat the migration is meant to remove.

### Install location

- **Root `package.json`** — not inside `src/frontend`.
  - Root already hosts `lint-staged`, `husky`, and the existing Prettier config. Repointing in place keeps `.husky/pre-commit` unchanged.
  - `src/frontend/package.json` carries application dependencies only (React, `html5-qrcode`, Vite, Vitest). Toolchain does not belong with app deps.
- `lint-staged` continues to live at the root and continues to be triggered by `.husky/pre-commit`. The rule simply swaps from `prettier --write` to `ultracite fix`.

### Ultracite `init` flag set (verified from `ultracite@7.9.4 --help`)

```
ultracite init \
  --pm npm \
  --linter oxlint \
  --frameworks react vitest \
  --editors universal \
  --agents "" \
  --hooks "" \
  --integrations "" \
  --skip-install \
  --quiet
```

- `--pm npm` — repo uses `package-lock.json`.
- `--linter oxlint` — explicit engine choice.
- `--frameworks react vitest` — Vitest is the test runner in `src/frontend`.
- `--editors universal` — writes `.vscode/settings.json`. Verify the generated file references the Oxc formatter, not Prettier.
- `--agents ""` — do not generate `AGENTS.md` / `CLAUDE.md` in this pass; OMP already provides `AGENTS.md` in this repo.
- `--hooks ""` — do not generate IDE-specific AI hooks this pass.
- `--integrations ""` — do not generate CI integrations this pass.
- `--skip-install` — we will install deps ourselves to keep `package-lock.json` deterministic.
- `--quiet` — non-interactive.

After `init`, run `npm install` (or `npm install ultracite@7.9.4 oxlint@1.76.0 oxfmt@0.61.0 -D` if `init` did not modify the lockfile).

### `.vscode/settings.json` precondition

For format-on-save to actually run in VS Code or Cursor, the file must:

1. Set `"editor.formatOnSave": true`.
2. Set `"editor.defaultFormatter"` to a non-Prettier formatter (the Oxc extension, or whatever Ultracite 7.9.4's pinned template writes).
3. Not reference the Prettier extension (`esbenp.prettier-vscode`).

If `ultracite init`'s generated file references Prettier, the migration fails this precondition — fall back to manually editing the file (or skip editor wiring this pass and document it as out-of-scope).

### Node engine compatibility

`oxfmt@0.61.0` requires `node ^20.19.0 || >=22.12.0`. If `node -v` on the developer's machine is outside this range, format-on-save fails with a clear engine error. This spec assumes the developer uses Node 20.19+ or Node 22.12+; older Node 20.x is unsupported.

### Test seams (validated in the **Testing Decisions** section)

- `npx ultracite doctor` — install wiring.
- `npx ultracite check` — clean lint state.
- `lint-staged` end-to-end on a fixture — the production-critical path.
- `npm run typecheck && npm test && npm run build` — downstream.
- `prettier --version` returns ENOENT — Prettier fully removed.

## Testing Decisions

### What "good test" means for a toolchain migration

- Each test must defend an observable **behavioral** seam, not a tooling detail.
- Snapshots of package.json content are out — version drift is the spec's job; tests exist to prove wiring works.
- Tests live in the existing test runner (`vitest`) where they assert behavior; fixture-level seam proofs are shell scripts run by the reviewer, not committed tests.

### Seam 1 — `ultracite doctor`

```
npx ultracite doctor
```

- **Pass criterion**: exits 0 with no `error` lines in stdout.
- **What it covers**: engines installed; config files exist; binary resolution works.
- **Failure mode surfaced**: missing native binding for the developer's OS (Oxfmt uses NAPI per-OS binaries).

### Seam 2 — `ultracite check` against the tree

```
npx ultracite check
```

- **Pass criterion**: exits 0.
- **What it covers**: the post-autofix lint state is clean.
- **Failure mode surfaced**: rules that are **not** auto-fixable (e.g. `react-hooks/exhaustive-deps` warnings on manually-written code). These must be triaged manually — they should not exist post-autofix in this repo's small tree, but if they do they get fixed in the same commit before `--write`.

### Seam 3 — `lint-staged` end-to-end on a fixture (production-critical path)

This seam proves the Husky → lint-staged → `ultracite fix` chain, which Seams 1 and 2 do **not** prove.

```
# Run from a throwaway worktree (not committed to the repo).
git checkout -b toolchain/verify-staged-files
echo "const foo = (x) =>{return x+x;}" > /tmp/seam3-fixture.tsx
git add /tmp/seam3-fixture.tsx   # or move into a tracked path first
npx lint-staged --diff="HEAD"    # modern lint-staged API; alternate: --no-stash
```

- **Pass criterion**: lint-staged runs `ultracite fix` (visible in its stdout) and rewrites the fixture file in place; the rewritten content matches what `npx ultracite fix /tmp/seam3-fixture.tsx` produces.
- **What it covers**: the production-pre-commit path. Without this seam, a misconfigured `lint-staged` rule could pass `doctor` and `check` while still failing the commit-time invocation.
- **Failure mode surfaced**: lint-staged version mismatch; CLI passing of file arguments not honored; ultracite silently doing nothing on staged files.
- This seam is **disposable** — the throwaway branch and fixture file are deleted after the run, not merged into the migration branch.

### Seam 4 — downstream pipelines still green

```
cd src/frontend && npm run build && npm run test
cd / && npm run typecheck
```

- **Pass criterion**: build succeeds, vitest exits 0, tsc exits 0.
- **What it covers**: autofix did not break the codebase (e.g. by rewriting code that depended on the original format).

### Seam 5 — Prettier fully removed

```
command -v prettier || echo OK_NO_PRETTIER   # shell-level
test ! -f node_modules/.bin/prettier && echo OK_NO_PRETTIER_LOCK   # lockfile-level
grep '"prettier"' package.json && exit 1 || echo OK_NO_PRETTIER_PKG   # package-level
```

- **Pass criterion**: prettier binary absent, no devDep declaration, no config block.
- **What it covers**: a partial migration that left Prettier installed would re-fight Ultracite at format time.

### Suite

- Existing `vitest` suite (4 test files: `__tests__/{programViews,session}.test.*` plus presumably tests under `__tests__/` per the `src/frontend/src/__tests__/` layout) continues to pass.
- No new tests are added by this spec. The seams are reviewer-time verifications, not assertions in the test suite.

## Out of Scope

- **ESLint**, **Stylelint**, **Biome** — explicitly not adopted. Reconsidering requires a new spec.
- **AI agent config files** (`AGENTS.md` for ultracite, Cursor rules, Copilot rules) — OMP already maintains an `AGENTS.md` in this repo. Ultracite's `--agents` flag is left empty.
- **Migration to Next.js** — out of scope per Spec 000 and the existing `src/frontend` Vite + React 19 design. Ultracite's preset works in both, but the engine choice (Oxlint+Oxfmt) is engine-stable across that change.
- **CI integration** (GitHub Actions, pre-PR checks) — implementation may add `.github/workflows/ultracite.yml` later. This spec stops at pre-commit + manual `check`.
- **Pre-existing source code rewrites** beyond what `ultracite fix` autofixes. The migration does not touch component internals beyond what Ultracite flags and fixes.
- **Renaming of `src/frontend/src/...`** (the unusual nested `src/` layout surfaced by `glob`) — separate concern; tracked only in migration Plan `2026-07-27-efcc-webapp-migration.md`.
- **Upgrading to a newer Ultracite major version** — pinned to 7.9.4. Any future upgrade is its own spec.

### Rollback path

If the migration is abandoned after commit:

1. Revert the migration commit (`git revert <sha>`).
2. Re-add `prettier` devDependency and config block.
3. Restore `lint-staged` to `"*": "prettier --ignore-unknown --write"`.
4. Remove `.vscode/settings.json` if introduced, and `oxlint.config.*` / `oxfmt.config.*` files.

This is one revert + one commit. Toolchain rollback is a deliberate, named action — it is **not** an emergency procedure.
