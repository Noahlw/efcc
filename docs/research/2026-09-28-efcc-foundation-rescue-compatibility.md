## Current baseline

`main` builds a Next `16.2.12` app with React `19.2.8` as a static export (`output: "export"`); one Worker routes `/api/*` and serves the export through its `ASSETS` binding. The D1 binding uses Wrangler's SQL migration directory. There are 38 tracked SQL migration files on `main`. [Next config](https://github.com/Noahlw/efcc/blob/b18828d42b6e152f2d29ed1f63df9c1681e59046/web/next.config.ts), [Worker config](https://github.com/Noahlw/efcc/blob/b18828d42b6e152f2d29ed1f63df9c1681e59046/web/wrangler.jsonc), [worker entry](https://github.com/Noahlw/efcc/blob/b18828d42b6e152f2d29ed1f63df9c1681e59046/web/worker.ts), [web package](https://github.com/Noahlw/efcc/blob/b18828d42b6e152f2d29ed1f63df9c1681e59046/web/package.json).

The live stack still has Next static export, not SSR. Its `next.config.ts` says to revisit ADR-0017 before switching to SSR/OpenNext. The unchanged Wrangler config still names `efcc-prototype-129`; the repository instructions prohibit using that stale host for deployment. Treat all stack evidence as local-only.

### Material Drizzle conflict

The live #644/#664 source contains an explicit, measured Drizzle decision that the new handoff must reconcile. The earlier plan tested only the published-announcement read on D1; it did **not** test a full ORM or schema/migration conversion. The trial passed 14 `home-worker` tests and typecheck, but added one production dependency and 24 net source lines while duplicating the Wrangler SQL schema, so it was removed; no performance claim was made. The current stack therefore contains no Drizzle dependency or adapter. [Recorded trial at #644/#664 head](https://github.com/Noahlw/efcc/blob/99546f9db9a476108f86ee2fa104317e29a9592f/docs/plans/2026-09-23-repo-wide-organization.md#L192-L208), [evidence disposition](https://github.com/Noahlw/efcc/blob/99546f9db9a476108f86ee2fa104317e29a9592f/.delivery/repo-wide-organization-implementation/evidence.json).

This narrow read-path result does not disprove the handoff's broader Drizzle direction. It does rule out claiming that Drizzle already reduced EFCC maintenance or that a typed read adapter proved migration safety. The next decision needs to state whether Drizzle owns typed queries, schema generation, the Wrangler migration SQL, or all three, then compare the whole maintenance surface while retaining raw SQL for database features the schema generator does not preserve. Keep exactly one D1 migration ledger.
